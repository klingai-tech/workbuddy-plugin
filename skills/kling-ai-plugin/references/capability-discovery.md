# 按账号发现能力

仅在准备生成设置、执行生成或选择模型时读取。只写提示词或分镜、索取缺失素材、查询任务、额度或素材时无需模型清单。

## 发现顺序

1. 从当前连接取得完整 `tools/list`（处理全部分页），只将实际存在且符合用户意图的入口作为候选。发现失败不能当作空列表或旧能力。
2. 实时 `who_am_i` schema 支持 `tools` 时，传入非空的候选工具集合。普通请求只查相关入口，视频按下方候选规则查找。用户明确要求最新视频模型时，覆盖实际工具描述中支持同一输出类型与意图的入口。未声明的筛选参数不得传入。
3. 以本次 `who_am_i.availableModels` 为账号能力的权威来源，在候选入口的 `models` 内匹配规范名/别名；否则按核心选型规则筛选。用户点名模型但当前筛选结果未命中时，补查当前连接其余已发现的生成入口，区分模型未返回与模型仅支持另一种输出类型；补查仅用于诊断，不能将其他媒体类型的模型当作本次生成候选。未返回、约束无法满足的模型不作为候选，不读取其推荐文档、不猜测其规格。
4. 选定一个“工具 + 模型”后，只以该模型完整的 `arguments`、`inputs` 和组合约束构造本次请求。保留必填项、默认值、枚举和说明中的依赖/互斥限制，不把其他模型的参数带入。按[参数模块加载表](model-parameters.md)决定还需读哪些文档。

## 视频候选入口

文生视频比较实际存在的 `text_to_video` 与 `omni_ref_video`，图生视频比较 `image_to_video` 与 `omni_ref_video`。关键帧、主体库和音频参考只查声明相关能力的入口。默认推荐其中满足全部必需条件的 `omni_ref_video` 可灵 4.0 模型。

用户限制入口或型号时按其范围筛选。动作迁移等专用需求发现声明该能力的入口。相关入口已成功发现但未返回兼容模型时，按[视频选型规则](../../kling-ai-generate-video/references/omni-video.md)处理。发现过程失败时刷新连接或报告具体问题，无法确认能力时停止。

## 复用与边界

- 同一次生成准备的选型和传参复用一次成功的能力响应；变更到未查询的入口时补读，不因读另一份 MD 重复请求。
- 过滤响应只覆盖所请求的入口，不能据此断言其他入口不可用或整个账号不支持某模型。补查仍未完成时，只说明“已查询的图像/视频入口未返回所请求模型”。用户改变规格后，已排除的模型可按新要求重新评估。
- 重新连接、切换账号/端点、用户说明会员权益已变化、收到能力变更通知或模型/参数被拒绝时，清除旧选型依据并重新发现。不得用会员名称、客户端版本、工具数量推断权限。
- 用户明确说明所请求模型已开通，但完整发现仍未返回时，按[模型能力不一致](troubleshooting.md#模型能力不一致)排查；这属于待查差异，不直接判定账号未获权限，也不自动回退旧模型提交。
- 未开放的枚举不从描述举例、历史记录或静态文档补入。用户要求的规格不支持时，说明当前限制与实际可用选项，不静默降低规格或探测生成。
- 工具描述、会员页或示例与 `who_am_i` 的模型能力不一致时，以 `who_am_i` 为准。若其返回缺失、失败，或无法按工具 `inputSchema` 编码合法请求，刷新相关发现；仍不一致则停止提交，不用其他来源补齐能力。
- 筛选能力按当前 `who_am_i` 的 `inputSchema` 使用；仅声明工具级筛选时，不虚构 `models`、`fields` 等查询参数。过滤工具能减少返回内容；对响应再做选择不能撤销已经进入上下文的 token。
- 本包不存账号能力快照或机密信息。可以在本次上下文保留选定模型的完整约束；不要向用户复述整份 schema、账号字段或未选模型列表。
- 会员套餐、当前余额和模型灰度分别判断：套餐说明提供权益背景，余额用实时额度响应，模型/规格用当前 `availableModels`。网页账号不自动视为 MCP 授权账号；官网权益不补入 MCP 未返回的模型或参数。仅当用户询问会员或遇到明确权益错误时，按[会员排查](troubleshooting.md#会员权益与可用能力)查看官网说明。
