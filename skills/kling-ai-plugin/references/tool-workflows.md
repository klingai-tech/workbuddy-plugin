# 生成提交与重试

仅在生成或已授权重试时读取。本文件不负责普通状态查询；提交受理后或只查任务时转到[任务结果](task-results.md)。

## 判断意图

| 用户请求 | 行为 |
| --- | --- |
| 创建作品、明确重试、编辑已有作品或制作新变体 | 输入完整后执行一次已授权的生成步骤；失败本身不构成重试授权 |
| “现在好了吗”、查看结果、刷新下载链接 | 查询已有任务，不重新生成 |
| 多个作品或跨媒体任务 | 将每个明确要求的步骤视为一次授权，按依赖顺序执行 |
| 上次提交超时或响应丢失 | 先恢复已知任务；不能把“未知”当作“未创建” |

同一目标复用 UUIDv7 `taskTraceId`；无关目标才创建新值。它用于追踪，不是幂等键。稳定作品标识为 `generationId`、`works[]` 序号和 `contentType`，不使用临时 URL 代替。

## 提交前与单次提交

1. 按[能力发现与复用](capability-discovery.md)获取相关工具和模型能力，复用本次准备阶段已读取的响应。按[创作与能力选择](../SKILL.md#创作与能力选择)选取满足需求的组合。只展示、推荐和调用当前账号实际返回的模型。
2. 用户的生成请求授权每个明确要求的步骤一次；只补齐会改变结果的缺失信息，不重复确认。实时工具要求的全能参考计费说明在提交前提供，不虚构价格。
3. 优先使用宿主提供且模型接受的引用；需要上传时按[素材流程](asset-workflows.md)完成两步上传。历史 Kling 作品在新生成前查询其任务一次，按原作品序号和类型取当前 URL；无法定位、刷新失败或资源仍不可用时停止，不拿旧 URL 重试。
4. 按[MCP 契约](mcp-contract.md)检查所选工具及模型的必填项、字段类型、枚举、数量和互斥关系。切换模型后重新构造请求，不携带旧模型参数。
5. 紧邻收费生成前查询 `query_membership_and_credits`。余额非正数、服务明确拒绝，或同一设置的实时预计消耗大于可用余额时，按下方流程暂缓生成。余额为正但未返回本次任务成本时，不声称一定充足。只读状态或素材查询无需查余额。
6. 每个已授权步骤只提交一次，保留返回的任务与追踪 ID。对用户显示“任务编号”；`creditsConsumed` 或提交受理不是完成证据。不要在准备工作结束后遗漏已授权提交。
7. 同一目标最多一个未终态收费任务。依赖前一步的后续生成只能在前一步成功且源作品明确后继续，不能把“已提交”当作依赖完成。

## 积分不足后的恢复

1. 在当前会话保留原任务的意图、工具、规范模型 ID、提示词、规格、素材槽位与宿主可用的原素材引用，以及 `taskTraceId`、提交状态和已知 `generationId`。当前余额以 `query_membership_and_credits` 为准。仅在实时服务提供同一设置的预计消耗时说明差额。
2. 给出当前连接返回且适用于该账号所在区域的正式充值入口。未返回正式入口时，引导用户在[可灵官网](https://klingai.com/)登录同一账号，从账号页面进入充值。测试或预发链接、自行拼接的支付地址和会话中的素材引用均不能用作充值入口。由用户自行完成充值。说明原任务的实际状态，并提示充值后回到当前会话回复“继续刚才的任务”。
3. 用户仅表示已充值时，可刷新额度并说明下一步。用户明确要求继续时，复用当前会话中唯一可确定的原任务。有多个候选时只问继续哪一个。已有 `generationId` 时，在查余额或准备提交前先查询原任务，按[任务结果](task-results.md)交付其状态或作品。此前未发出生成请求，或服务明确确认未创建且未扣费，才进入正常提交。原提交结果未知时按下方歧义规则处理。
4. 在原账号下重新核对余额、模型与素材有效性，沿用原规格及追踪编号。余额仍不足时保留原任务并说明现状。签名素材失效时，用当前会话仍可访问的原素材重新获取有效引用，只请用户补无法恢复的素材。原规格已不可用、需要换模型或改变付费设置时先由用户选择。条件满足后按单次提交规则执行。

## 歧义、失败与停止

提交响应不明确但已有 `generationId` 时查询该任务。未取得该次任务编号时，报告已知结果或错误，将无法确认的创建、扣费状态标为未知，然后停止。`query_tasks` 需要真实任务编号，无法用来查任务历史、余额或通过 `taskTraceId` 找回任务。余额未变或历史没有可见条目也无法确认是否创建或扣费。

余额、会员、队列、限流、素材或服务错误均不触发自动重试、切模型或变更用户意图。再次提交须有新的明确授权，即使上一次调用报错或用户后来未看到任务。用户明确要求重试时，先确认原提交状态。无法确认时，须由用户明确接受可能重复扣费的风险才提交替代任务。

当前步骤完成后继续用户已授权且条件满足的后续步骤；结果刷新、回落和成品检查交给[任务结果](task-results.md)。错误处理细节见[故障排查](troubleshooting.md)。
